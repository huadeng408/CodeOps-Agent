# 2026-08-14 进展：Python RAG 依赖可复现与阶段汇报约束

## 本轮范围

本轮只关闭一个可自动验证的多模态 RAG 基础设施缺口：此前
`orchestrator.rag` 在代码中直接导入 LangChain、FastAPI 和 HTTP 客户端，
但 `pyproject.toml` 没有声明可安装的 RAG extra，干净环境无法保证能够
收集 MinerU/PDF/结构化入库测试。没有修改 qrels、评测标签、索引、数据库、
Docker 卷、模型配置或密钥。

## IMPLEMENTED

- `pyproject.toml` 新增 `rag` optional dependency group，声明现有
  `orchestrator.rag` 的 FastAPI、HTTPX、Pydantic、Uvicorn、LangChain core/
  OpenAI/text splitters、LangGraph 与 typing-extensions 运行时依赖；它不
  影响只使用 Go harness 的默认安装。
- 新增 `tests/test_project_metadata.py`，冻结上述运行时导入必须由 `rag`
  extra 声明的契约，避免以后再出现“代码可导入但元数据遗漏”的假绿。
- `AGENT.md` 新增强制阶段结束报告：每次结束必须给出四条主线的证据加权
  百分比、最需补项、最大不确定性和最大遗漏，且不得把计划、标签、fixture
  或 preflight 当成完成证据。

## 证据边界与后续

- 此证据仅证明 Python RAG/MinerU 基础依赖可由声明复现，且已有局部测试可
  在干净环境运行；不证明视觉 encoder、视觉索引、ViDoRe/bbox bake-off 或
  多模态 qrels 已完成。
- O3 仍缺一份 current-HEAD 的真实 Phoenix 回读、严格父子链、官方 scorer
  和 checksum-valid receipt；不能用本轮依赖通过代替它。
- 评测集的语义 `DISPUTED` 标签不能作为重试失败；仅 transport/parse/validate
  失败项可进入受并发上限约束的恢复流程，真实人工复核仍未完成。

## 回滚边界

数据库、Elasticsearch alias/索引、MinIO、Kafka、Docker 卷、qrels、评测
sidecar 或任何密钥。
