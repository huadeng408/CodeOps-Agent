# 便携产品启动恢复超时

关联 [#27](https://github.com/huadeng408/CodeOps-Agent/issues/27) 与
[#42](https://github.com/huadeng408/CodeOps-Agent/issues/42)。本页先记录实际故障和修复范围，
不把准备或源码检查当作 200 轮完成。

## 已确认事实

clean `5f058572739b78d55f3b6f9efb66a71d4b962cd6` 的完整 CI 成功。
官方 v16 便携包从现有缓存构建，675 个源码输入、3225 个运行文件；
新 v10 在任何派发前冻结原 200 条请求、99 文件基线、满配置与实际资源。

新浏览器 Session 准备完成，但首个消息 POST 返回 503。Go 原生读回仅有 3 条准备事件，
0 accepted Run、0 模型调用、0/200 assistant turn。原失败、199 条未尝试请求及实际 POST 保留，
没有盲重发。该范围不是提供方模型失败。

只读检查确认 Python 监听地址与 launcher 注入地址一致；公开 gRPC Health 实测 16ms 返回正常。
Go continuation 仍未附着，裸错误为 `context deadline exceeded`，对应连接后的整批 Recover 阶段。
共享库当时有 234 个 stream／49,974 条事件／120,373,248 字节；只读 SQL 计数耗时 16ms。

恢复遍历在共同 5 秒 context 内反复执行完整 Session 视图、Run／Surface 和祖先、准入投影，
超时后下一次从头开始。部分检查所需的字段不需要完整 Surface。
尚未独立测量各 Go 子阶段的 CPU 占比，不能把全部时间归给某一条 Session 或一次投影。

## 修复计划与完成检查

1. 在公开 `SessionRunner.Recover` 边界复现大历史与 yielded 根场景；验证正常候选仍可恢复，
   原事实、祖先授权、链完整性、并发变化及新鲜 startup fence 均保留。
2. 消除重复读取与不需要的完整 Surface 投影；不只放宽超时，不绕过恢复，不引入第二事实源。
3. 定向及相关 Go 回归、vet、两轴审查、精确路径和秘密检查后提交，取得对应源码完整 CI。
4. 由新的独立便携包和冻结身份验证实际启动，再继续原完整 200 条请求。

## 实现与开发验证

恢复先读取并验证 metadata，用于拒绝已删除、已让出的任务；只有合资格候选才构建完整
Surface。完整的普通 `ModelTaskRoot` 仍检查整个认证祖先链，随后重新读取 startup fence，
再核对当前候选的完整 Surface 和原 head，最后才允许恢复写入。
普通快照的零值错误返回、Actor／owner 校验及未知计量语义不变。
准入历史中的活动调用计数改为单次回放内增量计算，不建立跨请求缓存或第二事实源。

公共 `SessionRunner.Recover` 用例使用独立 SQLite，包含 774 条事实的已让出任务和一个
可恢复任务。原实现分配 153,999,592 字节，超过 64 MiB 的粗粒度资源上限，RED 退出 1；
最终修复后同一用例分配 9,785,576 字节，所在定向回归退出 0，约减少 93.6%。
两次均确认旧任务事实不变、仅合资格任务完成；旧任务的读取次数仍为 2，
该结果证明减少了投影分配，不能宣称已经减少实际读取次数。

测试耗时包含夹具建立，编译等待另有记录，不用其总时长声称生产启动提速。
首次 180 秒编译超时未进入测试，独立保留为基础设施失败，没有计为行为 RED。

首次两轴审查发现合资格子任务取消恢复可能漏验父 Surface。隔离公开用例实际复现了
“父 checksum 合法、Surface 非法，Recover 虽报错仍追加 child 事实并调用一次取消回调”。
补上完整祖先校验后该用例通过，父子事实和回调均不变；另覆盖完整祖先读取期间新增 yield，
确认最终新鲜围栏仍能拒绝。原 RED、首次审查和中间结果均保留。
