# 本地 Code Agent 完备设计方案

> Go Harness（控制面） + Python LangGraph（编排面）双层架构，构建本地运行的 CLI Code Agent，目标实现 Claude Code 80%+ 核心能力。

---

## 一、项目概述

### 1.1 目标

构建一个本地运行的 CLI Code Agent，采用 **Go Harness + Python LangGraph** 双层架构。核心价值：

- 本地执行，数据不离开开发者机器
- Go 提供高性能工具执行、安全控制、会话管理
- Python LangGraph 提供灵活的多 Agent 编排、LLM 交互、上下文管理
- 通过 Deep Agents + 验证循环确保输出质量
- 对标 Claude Code 的 harness-driven 架构模式

### 1.2 核心设计理念

| 理念 | 说明 |
|------|------|
| Harness 驱动 | Go 控制对话循环和工具执行，LLM 只建议动作，harness 决定是否执行 |
| 本地优先 | 所有操作在本地执行，无需云端服务 |
| 渐进信任 | 三级权限模型：auto-allow / ask-once / always-ask |
| 可扩展 | Hooks + Skills + MCP 三重扩展机制 |
| 可观测 | Token 用量、执行状态、成本全程可见 |
| 容错 | 两次失败后切换策略，而非无限重试 |

### 1.3 为什么选择 Go + Python 双层架构

| 层 | 语言 | 理由 |
|----|------|------|
| Harness（控制面） | Go | 高性能并发、单二进制分发、强类型安全、适合系统级操作 |
| Orchestrator（编排面） | Python + LangGraph | LLM 生态成熟、图结构灵活、内置 checkpointer、Deep Agents |

这与 Claude Code 的架构理念一致：harness 负责"做事"（工具执行、权限检查、IO），orchestrator 负责"思考"（规划、推理、决策）。两者通过 gRPC 通信，职责清晰。

### 1.4 非目标

本阶段不实现：

- Slack bot / Linear integration / GitHub App auth
- 自动 push / 自动开 PR（除非用户明确要求）
- LangGraph Cloud 部署
- 多用户 Web UI
- IDE 插件（预留事件流接口）

### 2.2 Harness 驱动模型

本方案采用 Claude Code 验证过的 **Harness-Driven** 架构：

```text
用户输入 → Go Harness 接收
         → 发送到 Python Orchestrator（含历史消息）
         → LLM 返回文本 + tool_use 请求
         → Go Harness 检查权限
         → 执行工具（或请求用户确认）
         → 将结果返回 Orchestrator
         → 循环直到 LLM 不再请求工具
         → 最终文本输出给用户
```

关键原则：**LLM 只能建议动作，Harness 决定是否执行**。这确保了安全性——即使 LLM 被 prompt injection 攻击，Harness 层的权限检查仍然生效。

### 2.3 gRPC 通信协议

Go Harness 与 Python Orchestrator 之间通过 gRPC 双向流通信：

```protobuf
syntax = "proto3";
package codeagent;

service Orchestrator {
  // 主对话流 - 双向流式
  rpc Converse(stream HarnessMessage) returns (stream OrchestratorMessage);
  // 健康检查
  rpc Health(Empty) returns (HealthResponse);
}

message HarnessMessage {
  oneof payload {
    UserInput user_input = 1;
    ToolResult tool_result = 2;
    PermissionDecision permission_decision = 3;
    Signal signal = 4;  // Ctrl+C, session resume 等
  }
}

message OrchestratorMessage {
  oneof payload {
    TextChunk text = 1;           // 流式文本输出
    ToolRequest tool_request = 2;  // 请求执行工具
    PlanUpdate plan_update = 3;    // 计划更新
    TodoUpdate todo_update = 4;    // 任务列表更新
    AgentSpawn agent_spawn = 5;    // 请求启动子 Agent
    SessionMeta session_meta = 6;  // Token 用量等元信息
    Done done = 7;                 // 本轮结束
  }
}

message ToolRequest {
  string tool_name = 1;
  string parameters_json = 2;
  PermissionLevel required_permission = 3;
}

enum PermissionLevel {
  AUTO_ALLOW = 0;    // 只读操作，自动放行
  ASK_SESSION = 1;   // 本次会话询问一次
  ALWAYS_ASK = 2;    // 每次都询问
}
```

### 3.3 权限控制器

三级权限模型，对标 Claude Code 的 permission system：

```go
package permission

type Level int

const (
    AutoAllow  Level = iota  // 只读操作，无需确认
    AskSession               // 本会话首次使用时确认
    AlwaysAsk                // 每次都确认
)

type Controller struct {
    config     *Config
    allowlist  []AllowRule
    sessionApproved map[string]bool  // 本会话已批准的操作
}

// 默认权限分级
var DefaultPermissions = map[string]Level{
    "Read":     AutoAllow,
    "Glob":     AutoAllow,
    "Grep":     AutoAllow,
    "Edit":     AskSession,
    "Write":    AskSession,
    "Bash":     AlwaysAsk,   // 默认每次确认
    "Git":      AskSession,
    "WebFetch": AskSession,
}

// Allowlist 规则 - 用户可配置自动放行
type AllowRule struct {
    Tool    string `json:"tool"`
    Pattern string `json:"pattern"`  // 正则匹配参数
}

func (c *Controller) Check(tool string, params map[string]any) Decision {
    // 1. 检查 allowlist
    if c.matchAllowlist(tool, params) {
        return Approve
    }
    // 2. 检查默认权限级别
    level := c.getLevel(tool)
    switch level {
    case AutoAllow:
        return Approve
    case AskSession:
        if c.sessionApproved[tool] {
            return Approve
        }
        return AskUser
    case AlwaysAsk:
        return AskUser
    }
    return AskUser
}
```

### 3.4 Hook 引擎

Hooks 允许用户在工具执行前后自动运行 shell 命令（对标 Claude Code hooks）：

```go
package hooks

type HookType string

const (
    PreTool       HookType = "pre_tool"
    PostTool      HookType = "post_tool"
    PrePrompt     HookType = "pre_prompt"
    PostResponse  HookType = "post_response"
    Notification  HookType = "notification"
)

type Hook struct {
    Type    HookType `json:"type"`
    Matcher string   `json:"matcher"`  // 工具名或事件匹配
    Command string   `json:"command"`  // 要执行的 shell 命令
    Timeout int      `json:"timeout"`  // 超时秒数
}

type Engine struct {
    hooks []Hook
}

func (e *Engine) Execute(hookType HookType, context HookContext) (*HookResult, error) {
    for _, h := range e.hooks {
        if h.Type == hookType && h.matches(context) {
            result := e.runCommand(h.Command, h.Timeout, context.Env())
            if result.ExitCode != 0 {
                return result, ErrHookBlocked
            }
        }
    }
    return nil, nil
}
```

配置示例（settings.json）：

```json
{
  "hooks": [
    {
      "type": "pre_tool",
      "matcher": "Bash",
      "command": "echo 'Running: ${TOOL_PARAMS}' >> ~/.agent/audit.log"
    },
    {
      "type": "post_tool",
      "matcher": "Edit",
      "command": "ruff check ${FILE_PATH} --fix"
    }
  ]
}
```

### 3.5 工具执行引擎

所有工具在 Go 侧执行，提供沙箱化、超时控制、审计日志：

```go
package tools

type ToolExecutor struct {
    permission *permission.Controller
    hooks      *hooks.Engine
    undo       *UndoManager
    metrics    *Metrics
    sandbox    *Sandbox
}

type ToolCall struct {
    Name       string
    Params     map[string]any
    Permission PermissionLevel
}

type ToolResult struct {
    Success bool
    Output  string
    Error   string
    Elapsed time.Duration
    Tokens  int  // 输出内容的估算 token 数
}

func (e *ToolExecutor) Execute(ctx context.Context, call ToolCall) (*ToolResult, error) {
    // 1. Pre-hook
    if hookResult, err := e.hooks.Execute(hooks.PreTool, call.Context()); err != nil {
        return &ToolResult{Success: false, Error: hookResult.Stderr}, nil
    }

    // 2. 权限检查
    decision := e.permission.Check(call.Name, call.Params)
    if decision == permission.AskUser {
        approved := e.requestUserApproval(call)
        if !approved {
            return &ToolResult{Success: false, Error: "user denied"}, nil
        }
    }

    // 3. 沙箱化执行
    result := e.sandbox.Run(ctx, call)

    // 4. 记录 undo 信息（仅文件操作）
    if isFileOp(call.Name) {
        e.undo.Record(call, result)
    }

    // 5. Post-hook
    e.hooks.Execute(hooks.PostTool, call.ContextWithResult(result))

    // 6. 记录 metrics
    e.metrics.RecordToolCall(call.Name, result.Elapsed, result.Success)

    return result, nil
}
```

```go
package session
```

### 3.7 Worktree 管理器

Git worktree 隔离，确保实验性修改不影响主分支：

```go
package worktree

type Manager struct {
    baseDir string
    active  map[string]*Worktree
}

type Worktree struct {
    Path   string
    Branch string
    BaseRef string
    CreatedAt time.Time
}

func (m *Manager) Create(name string, baseRef string) (*Worktree, error) {
    path := filepath.Join(m.baseDir, ".agent", "worktrees", name)
    branch := fmt.Sprintf("agent/%s", name)

    cmd := exec.Command("git", "worktree", "add", "-b", branch, path, baseRef)
    if err := cmd.Run(); err != nil {
        return nil, err
    }

    wt := &Worktree{Path: path, Branch: branch, BaseRef: baseRef}
    m.active[name] = wt
    return wt, nil
}

func (m *Manager) Remove(name string, discardChanges bool) error {
    wt := m.active[name]
    if !discardChanges && wt.HasUncommittedChanges() {
        return ErrUncommittedChanges
    }
    exec.Command("git", "worktree", "remove", wt.Path).Run()
    exec.Command("git", "branch", "-D", wt.Branch).Run()
    delete(m.active, name)
    return nil
}
```

## 四、Python LangGraph Orchestrator 详细设计

### 4.1 职责边界

Python Orchestrator 负责所有"智能"相关的逻辑：

| 模块 | 职责 |
|------|------|
| 主图（StateGraph） | 对话路由、工具调用决策、响应生成 |
| Deep Agents | 子 Agent 生成与管理 |
| 上下文压缩器 | 智能 compaction，保留关键信息 |
| Plan 管理器 | 计划模式的进入/退出/审批 |
| 记忆系统 | 文件式持久记忆，跨会话可用 |
| Skill 管理器 | 技能发现、加载、执行 |
| 错误恢复器 | 失败策略切换 |

| Prompt 构建器 | System prompt 动态组装 |
| Todo 管理器 | 任务列表跟踪 |

### 4.2 主图设计

```python
from langgraph.graph import StateGraph, END
from langgraph.checkpoint.postgres import PostgresSaver

class AgentState(TypedDict):
    messages: Annotated[list, add_messages]
    plan: Optional[Plan]
    todos: list[Todo]
    context_budget: int
    tool_calls_this_turn: int
    error_count: int
    current_strategy: str

def build_main_graph() -> StateGraph:
    graph = StateGraph(AgentState)

    # 节点
    graph.add_node("route", route_node)
    graph.add_node("call_llm", call_llm_node)
    graph.add_node("process_tools", process_tools_node)
    graph.add_node("compact", compact_node)
    graph.add_node("respond", respond_node)
    graph.add_node("error_recovery", error_recovery_node)

    # 边
    graph.add_edge(START, "route")
    graph.add_conditional_edges("route", route_decision, {
        "normal": "call_llm",
        "plan_mode": "call_llm",
        "compact_needed": "compact",
        "resume": "call_llm",
    })
    graph.add_conditional_edges("call_llm", after_llm, {
        "has_tools": "process_tools",
        "done": "respond",
        "error": "error_recovery",
    })
    graph.add_conditional_edges("process_tools", after_tools, {
        "continue": "call_llm",
        "compact_needed": "compact",
        "error": "error_recovery",
    })
    graph.add_edge("compact", "call_llm")
    graph.add_conditional_edges("error_recovery", recovery_decision, {
        "retry": "call_llm",
        "switch_strategy": "call_llm",
        "give_up": "respond",
    })
    graph.add_edge("respond", END)

    return graph.compile(checkpointer=PostgresSaver.from_conn_string(DB_URL))
```

### 4.3 路由节点

```python
def route_node(state: AgentState) -> dict:
    messages = state["messages"]
    last_msg = messages[-1]

    # 检查是否需要压缩
    total_tokens = estimate_tokens(messages)
    if total_tokens > state["context_budget"] * 0.8:
        return {"next": "compact_needed"}

    # 检查是否是恢复的会话
    if state.get("resuming"):
        return {"next": "resume"}

    # 检查是否在计划模式
    if state.get("plan") and state["plan"].status == "drafting":
        return {"next": "plan_mode"}

    return {"next": "normal"}
```

```python
    )

    # 流式输出文本部分
    new_messages = []
    for chunk in response:
        if chunk.type == "text":
            yield OrchestratorMessage(text=TextChunk(content=chunk.text))
        elif chunk.type == "tool_use":
            new_messages.append(chunk)

    return {"messages": new_messages}
```

### 4.5 上下文压缩器（Compaction）

对标 Claude Code 的自动 compaction 机制：

```python
class ContextCompactor:
    """
    智能压缩而非简单截断。
    保留：system prompt、最近 N 轮对话、关键工具结果摘要。
    压缩：早期对话轮次、大段工具输出。
    """

    def __init__(self, llm_client, target_ratio: float = 0.5):
        self.llm = llm_client
        self.target_ratio = target_ratio

    async def compact(self, messages: list, budget: int) -> list:
        current_tokens = estimate_tokens(messages)
        target_tokens = int(budget * self.target_ratio)

        if current_tokens <= target_tokens:
            return messages

        # 分区：保护区 + 可压缩区
        protected = messages[-6:]  # 最近 3 轮对话
        compressible = messages[:-6]

        # 用 LLM 生成摘要
        summary = await self.llm.chat(
            model="gpt-4o-mini",  # 用小模型压缩
            system="Summarize this conversation history concisely. "
                   "Preserve: key decisions, file paths mentioned, "
                   "current task state, errors encountered.",
            messages=[{"role": "user", "content": format_for_summary(compressible)}],
        )

        # 构建压缩后的消息列表
        compressed = [
            {"role": "system", "content": f"[Conversation summary]\n{summary}"},
            *protected,
        ]

        return compressed
```

### 7.1 设计理念

| General | 通用任务执行 | 可选 worktree |

| Background | 后台长时间运行 | worktree 隔离 |

### 7.3 实现

```python
class DeepAgentManager:
    def __init__(self, orchestrator_client, worktree_manager):
        self.client = orchestrator_client
        self.worktree = worktree_manager
        self.active_agents: dict[str, AgentHandle] = {}

    async def spawn(self, request: AgentSpawnRequest) -> AgentHandle:
        """启动子 Agent"""
        # 决定是否需要 worktree 隔离
        isolation = None
        if request.isolation == "worktree":
            isolation = await self.worktree.create(request.name)

        # 创建独立的 LangGraph 子图实例
        sub_graph = build_sub_agent_graph(
            agent_type=request.agent_type,
            tools=request.allowed_tools,
            working_dir=isolation.path if isolation else request.working_dir,
        )

        handle = AgentHandle(
            id=generate_id(),
            graph=sub_graph,
            isolation=isolation,
            status="running",
        )
        self.active_agents[handle.id] = handle

        # 异步执行
        if request.run_in_background:
            asyncio.create_task(self._run_background(handle, request.prompt))
        else:
            result = await self._run_foreground(handle, request.prompt)
            handle.result = result

        return handle

    async def _run_foreground(self, handle: AgentHandle, prompt: str) -> str:
        """前台执行，阻塞等待结果"""
        result = await handle.graph.ainvoke({"messages": [{"role": "user", "content": prompt}]})
        handle.status = "completed"
        return extract_final_response(result)

    async def _run_background(self, handle: AgentHandle, prompt: str):
        """后台执行，完成后通知"""
        try:
            result = await handle.graph.ainvoke({"messages": [{"role": "user", "content": prompt}]})
            handle.status = "completed"
            handle.result = extract_final_response(result)
            # 通知主 Agent
            await self.client.notify(AgentCompleteNotification(
                agent_id=handle.id,
                result=handle.result,
            ))
        except Exception as e:
            handle.status = "failed"
            handle.error = str(e)
```

## 九、错误恢复机制

### 9.1 核心原则

对标 Claude Code 的"两次失败后切换策略"原则：

```python
class ErrorRecovery:
    MAX_RETRIES_SAME_STRATEGY = 2

    def __init__(self):
        self.error_history: list[ErrorRecord] = []
        self.current_strategy: str = "default"

    def handle_error(self, error: ToolError) -> RecoveryAction:
        self.error_history.append(ErrorRecord(
            error=error,
            strategy=self.current_strategy,
            timestamp=time.time(),
        ))

        # 统计当前策略的连续失败次数
        consecutive = self._count_consecutive_failures()

        if consecutive < self.MAX_RETRIES_SAME_STRATEGY:
            return RecoveryAction(type="retry", message="Retrying with minor adjustment")

        # 两次失败，切换策略
        new_strategy = self._select_alternative_strategy(error)
        if new_strategy:
            self.current_strategy = new_strategy
            return RecoveryAction(
                type="switch_strategy",
                strategy=new_strategy,
                message=f"Approach failed twice. Switching to: {new_strategy}",
            )

        # 无可用替代策略
        return RecoveryAction(
            type="give_up",
            message="Multiple approaches failed. Reporting to user.",
        )

    def _select_alternative_strategy(self, error: ToolError) -> Optional[str]:
        strategies = {
            "file_not_found": ["search_glob", "search_grep", "ask_user"],
            "permission_denied": ["request_permission", "alternative_path"],
            "syntax_error": ["read_context", "smaller_edit", "rewrite"],
            "test_failure": ["read_test", "check_deps", "isolate_failure"],
            "build_failure": ["check_imports", "check_types", "rollback"],
        }
        available = strategies.get(error.category, [])
        # 排除已尝试过的
        tried = {r.strategy for r in self.error_history}
        for s in available:
            if s not in tried:
                return s
        return None
```

### 9.2 策略切换示例

```text
场景：编辑文件失败（old_string 不唯一）
  尝试 1: 扩大上下文使 old_string 唯一 → 失败
  尝试 2: 使用 replace_all → 失败（不适用）
  切换策略: 先 Read 文件确认当前内容，再重新构造 Edit
```

```go
package safety

type RiskLevel int

const (
    Safe       RiskLevel = iota  // ls, cat, echo
    Low                          // go build, npm test
    Medium                       // git commit, npm install
    High                         // rm -rf, git push --force
    Forbidden                    // rm -rf /, shutdown

var dangerousPatterns = []DangerPattern{
    {Pattern: `rm\s+-rf\s+/`, Level: Forbidden, Reason: "recursive delete from root"},
    {Pattern: `git\s+push\s+--force\s+(origin\s+)?(main|master)`, Level: Forbidden, Reason: "force push to main"},
    {Pattern: `git\s+reset\s+--hard`, Level: High, Reason: "destructive git reset"},
    {Pattern: `>(\/etc|\/usr|\/sys)`, Level: Forbidden, Reason: "write to system directory"},
    {Pattern: `curl.*\|\s*(bash|sh)`, Level: High, Reason: "pipe URL to shell"},
    {Pattern: `rm\s+-rf`, Level: High, Reason: "recursive force delete"},
    {Pattern: `git\s+push`, Level: Medium, Reason: "push to remote"},
    {Pattern: `npm\s+publish`, Level: High, Reason: "publish package"},
}

func AnalyzeCommand(cmd string) (RiskLevel, string) {
    for _, p := range dangerousPatterns {
        if p.Matches(cmd) {
            return p.Level, p.Reason

    return Safe, ""
}
```

```go
package mcp

type Manager struct {
    servers map[string]*ServerProcess
    tools   map[string]ToolDefinition  // MCP 工具注册表
}

type ServerProcess struct {
    Name    string
    Cmd     *exec.Cmd
    Stdin   io.WriteCloser
    Stdout  io.ReadCloser
    Status  string
}

func (m *Manager) LoadConfig(configPath string) error {
    cfg, err := parseConfig(configPath)
    if err != nil {
        return err
    }
    for name, serverCfg := range cfg.Servers {
        if err := m.startServer(name, serverCfg); err != nil {
            log.Warn("MCP server failed to start, degrading gracefully",
                "server", name, "error", err)
            continue  // 降级：跳过失败的 server
        }
    }
    return nil
}

func (m *Manager) startServer(name string, cfg ServerConfig) error {
    cmd := exec.Command(cfg.Command, cfg.Args...)
    cmd.Env = buildEnv(cfg.Env)

    stdin, _ := cmd.StdinPipe()
    stdout, _ := cmd.StdoutPipe()

    if err := cmd.Start(); err != nil {
        return err
    }

    proc := &ServerProcess{Name: name, Cmd: cmd, Stdin: stdin, Stdout: stdout, Status: "running"}
    m.servers[name] = proc

    // 初始化：获取工具列表
    tools, err := m.listTools(proc)
    if err != nil {
        proc.Status = "degraded"
        return err
    }
    for _, tool := range tools {
        m.tools[fmt.Sprintf("mcp_%s_%s", name, tool.Name)] = tool
    }
    return nil
}

func (m *Manager) CallTool(serverName, toolName string, params json.RawMessage) (*ToolResult, error) {
    proc := m.servers[serverName]
    if proc == nil || proc.Status != "running" {
        return nil, fmt.Errorf("MCP server %s not available", serverName)
    }
    // JSON-RPC 2.0 调用
    return m.jsonRPCCall(proc, "tools/call", map[string]any{
        "name":      toolName,
        "arguments": params,
    })
}

func (m *Manager) Shutdown() {
    for _, proc := range m.servers {
        proc.Cmd.Process.Signal(os.Interrupt)
        proc.Cmd.Wait()
    }
}
```

## 十二、Todo 管理器

### 12.1 设计理念

对标 Claude Code 的 TodoWrite 工具。Agent 在处理复杂任务时自动创建任务列表，实时更新进度，让用户清晰看到工作状态。

### 12.2 实现

```python
@dataclass
class Todo:
    content: str          # 任务描述（祈使句）
    active_form: str      # 进行时描述（用于显示）
    status: Literal["pending", "in_progress", "completed"]

class TodoManager:
    def __init__(self):
        self.todos: list[Todo] = []

    def update(self, todos: list[Todo]):
        """整体更新任务列表"""
        self.todos = todos
        self._emit_update()

    def mark_complete(self, index: int):
        """标记任务完成"""
        self.todos[index].status = "completed"
        self._emit_update()

    def mark_in_progress(self, index: int):
        """标记任务进行中（同时只能有一个）"""
        for t in self.todos:
            if t.status == "in_progress":
                t.status = "pending"
        self.todos[index].status = "in_progress"
        self._emit_update()

    def _emit_update(self):
        """发送 TodoUpdate 事件到 Harness"""
        yield OrchestratorMessage(todo_update=TodoUpdate(
            todos=[asdict(t) for t in self.todos]
```

```go
    "gpt-4o":      {InputPer1K: 0.0025, OutputPer1K: 0.01},
    "gpt-4o-mini": {InputPer1K: 0.00015, OutputPer1K: 0.0006},
    "claude-sonnet-4-6": {InputPer1K: 0.003, OutputPer1K: 0.015},

    c.mu.Lock()
    defer c.mu.Unlock()

    pricing := modelPricing[model]
    cost := float64(tokensIn)/1000*pricing.InputPer1K +
            float64(tokensOut)/1000*pricing.OutputPer1K

    c.session.TotalTokensIn += tokensIn
    c.session.TotalTokensOut += tokensOut
    c.session.TotalCost += cost
    c.current.TokensIn += tokensIn
    c.current.TokensOut += tokensOut
}

// 状态栏显示
func (c *Collector) StatusLine() string {
    return fmt.Sprintf("Tokens: %d in / %d out | Cost: $%.4f | Tools: %d",
        c.session.TotalTokensIn, c.session.TotalTokensOut,
        c.session.TotalCost, c.session.ToolCalls)
}
```

### 13.2 Token 预算控制

```python
class TokenBudget:
    def __init__(self, max_tokens: int = 1_000_000, max_cost: float = 5.0):
        self.max_tokens = max_tokens
        self.max_cost = max_cost
        self.used_tokens = 0
        self.used_cost = 0.0

    def check(self) -> BudgetStatus:
        if self.used_cost >= self.max_cost:
            return BudgetStatus.EXCEEDED
        if self.used_tokens >= self.max_tokens * 0.9:
            return BudgetStatus.WARNING
        return BudgetStatus.OK

    def on_exceeded(self) -> str:
        return ("Token budget exceeded. Session paused. "
                "Use /budget to increase or start a new session.")
```

## 二十、关键设计决策记录

### ADR-001: 为什么用 gRPC 而非 HTTP/WebSocket

- gRPC 双向流天然适合"harness 发送输入，orchestrator 流式返回多种消息类型"的场景
- 强类型 proto 定义确保 Go/Python 之间的契约清晰
- 性能优于 HTTP JSON（二进制序列化）
- 代码生成减少手写 boilerplate

### ADR-002: 为什么 Checkpoint 用 PostgreSQL 而非 SQLite

- LangGraph 的 PostgresSaver 是官方推荐的生产级 checkpointer
- 支持并发访问（多个子 Agent 同时写入）
- 开发环境用 docker-compose 一键启动
- 如果用户不想装 PostgreSQL，可降级为 MemorySaver（不持久化）

### ADR-003: 为什么工具执行在 Go 侧而非 Python 侧

- 安全性：权限检查、沙箱化、命令分析都在 Go 的强类型系统中实现
- 性能：文件 IO、进程管理、glob 匹配在 Go 中更高效
- 隔离：即使 Python orchestrator 崩溃，Go harness 仍能保护文件系统
- 单一职责：Python 只负责"思考"，Go 负责"执行"

### ADR-004: 为什么记忆用文件而非数据库

- 对标 Claude Code 的设计：记忆是 Markdown 文件，人类可读可编辑
- 可以提交到 git（项目级记忆）
- 不需要额外依赖
- 简单的关键词匹配足够，不需要向量搜索（本地场景）

## 二十二、进一步改进建议（对标 Claude Code 最先进 Harness）

以下是基于 Claude Code 实际架构的深度分析，当前方案仍可进一步提升的方向：

### 22.1 并行工具调用（P0）

Claude Code 支持 LLM 在单次响应中请求多个独立工具调用，harness 并行执行。当前 gRPC 协议应扩展支持批量请求：

```protobuf
message ToolRequestBatch {
  repeated ToolRequest requests = 1;
  bool parallel = 2;  // true = 可并行执行
}
```

Go 侧用 goroutine 并行执行：

```go
func (e *ToolExecutor) ExecuteBatch(ctx context.Context, batch []ToolCall) []ToolResult {
    results := make([]ToolResult, len(batch))
    var wg sync.WaitGroup
    for i, call := range batch {
        wg.Add(1)
        go func(idx int, c ToolCall) {
            defer wg.Done()
            results[idx], _ = e.Execute(ctx, c)
        }(i, call)
    }
    wg.Wait()
    return results
}
```

### 22.2 Prompt Cache 感知调度（P0）

Anthropic/OpenAI 的 prompt cache TTL 约 5 分钟。Harness 应感知 cache 行为：

- System prompt 前缀保持稳定（cacheable 段放最前面）
- Compaction 时不改变 system prompt 结构
- 子 Agent 复用父 Agent 的 system prompt 前缀
- Metrics 中记录 cache hit/miss 率

```python
class SystemPromptBuilder:
    def build(self, state: AgentState) -> str:
        sections = [
            # cacheable 段放前面，最大化 cache 命中
            PromptSection("identity", IDENTITY_PROMPT, cacheable=True),
            PromptSection("capabilities", CAPABILITIES_PROMPT, cacheable=True),
            PromptSection("tools", self._build_tools(state), cacheable=True),
            PromptSection("project", load_agent_md(state["working_dir"]), cacheable=True),
            # 动态段放后面
            PromptSection("memory", self._build_memory(state), cacheable=False),
            PromptSection("session", self._build_session(state), cacheable=False),
        ]
        sections.sort(key=lambda s: (not s.cacheable, s.priority))
        return "\n\n".join(s.content for s in sections if s.content)
```

### 22.4 工具输出截断与智能摘要（P1）

```go
const (

)

func (e *ToolExecutor) truncateOutput(output string) (string, bool) {
    lines := strings.Split(output, "\n")
    if len(lines) > MaxToolOutputLines {
        truncated := strings.Join(lines[:MaxToolOutputLines], "\n")
        truncated += fmt.Sprintf("\n\n[Output truncated: %d lines total, showing first %d]",

    }
    return output, false
}
```

### 22.8 用户中断的精细处理（P1）

```go
func (a *App) setupSignalHandling() {
    sigCh := make(chan os.Signal, 1)
    signal.Notify(sigCh, os.Interrupt)

    go func() {
        consecutiveInterrupts := 0
        lastInterrupt := time.Time{}

        for range sigCh {
            now := time.Now()
            if now.Sub(lastInterrupt) < 500*time.Millisecond {
                consecutiveInterrupts++
            } else {
                consecutiveInterrupts = 1
            }
            lastInterrupt = now

            if consecutiveInterrupts >= 3 {
                os.Exit(1)  // 三次快速 Ctrl+C = 强制退出
            }
            // 单次 Ctrl+C = 中断当前工具执行
            a.cancelCurrentTool()
            a.renderer.Print("\n[Interrupted. You can give new instructions.]\n")
        }
    }()
}
```

### 22.11 最关键的架构认知

Claude Code 的核心设计哲学是：**Harness 是对话循环的主人，LLM/Graph 只是被调用的组件。**

```text
Go Harness 主循环:
  while true:
    input = readUserInput()
    messages.append(input)
    while true:  // 内循环：一直调用 LLM 直到不再请求工具
      response = callOrchestrator(messages)  // 单次 LLM 调用
      messages.append(response)
      if response.hasToolCalls():
        for tool in response.toolCalls:
          result = executeTool(tool)  // Go 本地执行
          messages.append(result)
      else:
        break  // LLM 不再请求工具，本轮结束
    renderFinalResponse(response)
```

当前方案保留了 LangGraph 图作为控制流中心，这是一个合理的取舍：
- **优势**：保留 LangGraph 的图灵活性（审批中断、多分支路由、checkpoint 恢复）
- **代价**：与 Claude Code 的"harness 完全掌控"模式有差异

建议的折中方案：**Go 掌控外层循环（用户交互、会话管理），LangGraph 掌控内层循环（单轮对话内的 LLM 调用和工具编排）**。这样既保留了 LangGraph 的价值，又让 Go 作为最终的安全屏障。
